design
Consumes the real d-5 factory/codec/Storage/transaction declarations and prototype result. Own implementation after explicit staged manifest/lib.rs handoff; no redefinition of contract.rs. OneThe writer thread exclusively owns the only write-mode SQLite connection; one database handle ownsroutes onewrites writerthrough queue/onlyits writequeue, connectionand plusreader workers use read-only workers.connections. Copy only proven channel/reader plumbing from atm-core, implement the new future mechanism with explicit prototype risk. Per root writer constraints, only writer runtime drives Runtime::block_on; readers use blocking_recv, no runtime.
Read-write transaction producer executes in one savepoint inside queued outer transaction; failed/suspended body rolls back that savepoint, outer commit precedes success reply. Owned Send+'static producer creates a fresh future per attempt; SQLite body can await only tx operations. Actual Pending is rejected, even if a call would later become ready. Runtime is not the analyzer. Worker catch_unwind translates panic to typed worker-failed state, drains/fails every outstanding reply and closes admission; subsequent callers get typed failure. No public API panics.
No table-specific code or dependency on sc-cron. Storage<T> uses registered generic descriptor/codec; application chooses/migrates schema through generic engine API. d-6 removes SQLx SQLite only in its owned store wrapper manifest after d-5 additive registration. Package/default features remain consumer-neutral. Direct native identity is proved by cargo tree -i libsqlite3-sys; absence of sqlx-sqlite by cargo tree, not lockfile. Generic backend/native mix compile probes are boundary evidence, not complete generated app proof.
+ The d-5-owned root already registers rusqlite >=0.41; this sprint does not edit Cargo.toml. Only SqliteDatabase/Store<T> typed APIs are public; raw connection/SQL machinery is private. wait_closed returns typed completion/failure for existing daemon shutdown control.
