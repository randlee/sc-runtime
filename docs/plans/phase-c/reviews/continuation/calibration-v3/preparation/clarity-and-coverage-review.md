## Semantic checks

The shape boundary has a concrete counterexample: output may satisfy a broad JSON source while being an array, so an object-specific statement is not entailed. Conversely an explicitly object-specific quote supports an object statement. The explicit array/object conflict protects against treating all container words as interchangeable.

The channel boundary similarly preserves possibilities: a source that omits a destination does not alone select stdout, and a source naming logs/errors does not alone map their actors and destinations onto the request logger's standard streams. Explicit stdout sources are positive contrasts; an explicit stderr requirement paired with a stdout statement is negative.

The concrete-canary positive instantiates a requested test with non-secret fixture data under the genuinely approved test-data rule. It adds no environment-variable trigger or output/storage surface. The negative adds both an environment-source binding and file deletion, which are unsupported independent product duties. Concrete data is not itself treated as policy invention.

The shared generic policy does not supply an encryption algorithm. Algorithm authority in the v3 positive comes directly from the synthetic source quote. The old hypothetical algorithm approval/denial contexts remain preserved in the predecessor but are not promoted into newly approved human facts.

All quote texts in new contrasts are explicitly synthetic benchmark inputs. They are not attributed to the actual human approver as consumer requirements. The human provenance authorizes the calibration construct and the five revisions, not fictional project decisions.
