# d-7: postgres-storage

## Description

### Deliverables
1. Implement Postgres's share of the one shared sc-storage Storage<T> trait and its single AtomicStorage::transaction(spec, producer) operation for several row operations as one atomic unit; SQLite (d-6), Postgres (d-7) and MySQL (d-8) each implement that same contract (ANC-032/033). Implement PostgresStore<T>: sc-storage Storage<T> plus the same generic AtomicStorage::transaction(spec, producer), generic row mapping, generated-key insert/delete and engine factory. App owns schema/migrations; no WidgetRow, CronRow or consumer SQL lives in the generic engine (ANC-032/033/034/035).
2. Replace the sqlx umbrella with sqlx-core/sqlx-postgres/sqlx-macros >=0.9, no upper bound. Qualify real live query macros, migrations/offline replacement and CLI paths, preserving typed errors and existing wrapper behavior (REQ-RUN-0002/0302/0321; ANC-037).
3. Bound serialization retries and pool-acquire/statement/transaction waits in EngineConfig using finite defaults and validated configuration. Exhaustion/deadline yields typed StorageError with retryability/recovery, never an infinite loop. Controlled conflicts/timeouts test the bound; no sleeps or load races. Retry knobs are engine policy, not extra transaction properties (NFR-RUN-0002/0009).

### This sprint does not close
Real production composition, generated database security and registry migration are d-11; no generator/sync/permission feature is added.

## Acceptance criteria

boundary:template-store-postgres — contract tests pass against an actual Postgres service with named CI prerequisites, write/read and typed error behavior; workspace/boundary checks pass. A fake/sqlite stand-in is not live Postgres proof. d-11 owns final surfaces/template composition.
