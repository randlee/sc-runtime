# d-5: storage-contract

## Description

### Deliverables
1. Define real production Storage<T>, row mapping, Transform, StorageCommands/StorageCommandError and a named retryable atomic transaction producer/future in sc-storage. No storage backend CRATE includes any type, schema or SQL specific to a consumer table; CronRow/CronStorage live in sc-cron, application rows live in schema/service (ANC-034). Add std-only test doubles — REQ-RUN-0328; ADR-RUN-0020/0021; ANC-012/032/033/034.
2. Prototype the new transaction-future mechanism before freezing it. One generic transaction operation runs several row operations as one atomic unit; SQLite, Postgres and MySQL each implement this operation. Producer owns Send+'static captures and creates a fresh body for retries; only name and read-only/read-write are declared transaction properties (ANC-033). SQLite evaluates it in one queued savepoint and refuses actual suspension; Postgres/MySQL use begin/commit with serialization retry. The generic observability wrapper records name, queue wait, run time, row operation count and outcome. Settle exact handle/future shape and row mapping from prototype evidence, including whether transactions span row types: freeze the demonstrated multi-type contract if supported, otherwise the demonstrated single-row-type contract and its limitation; if neither passes atomic/retry/safety cases, closure stays blocked — ANC-033; NFR-RUN-0002.
3. Define the real backend factory/codec declarations in writer src/contract.rs and export them; define template schema WidgetStorage/OpenWidgetStore/StoresView extension signatures preserving existing create/get/delete. Prototype proposed option (a), the template create/get/delete extension over generic storage. Owner (randlee) ratification of this extension and the frozen transaction/row/migration shape is PENDING and gates d-5 closure; ADR-RUN-0020/0021 remain Proposed, not binding. Downstream sprints consume only the ratified contract. Compile conformance cases against real exported traits, never copies — REQ-RUN-0201/0328; ADR-RUN-0020.
4. Define CronRow/CronStorage declarations in sc-cron; provide only generic storage conformance/double at tests/support/storage, with no cron rows or policy. Register both generic support and d-9-owned tests/support/cron-storage as allowed test-double paths. sc-cron will implement domain guarantees ONCE over the atomic unit, not in backends — REQ-CRON-0004/0020/0021; ANC-030/031/033/034.
5. Make additive shared contract registrations in workspace/template manifests and boundaries. Root registers sc-storage plus one rusqlite >=0.41 requirement with no upper bound inherited by sc-cron/writer; absorb legacy API drift and retain its existing SQLite tests. No version bump here: development stays0.2.0, release owner d-12 coordinates0.3.0. Own crates/sc-cron/Cargo.toml Windows dev-dependency pin removal: win32job >=2.0.3 and waitpid-any >=0.3.0, preserving their existing purpose comments; d-9 leaves those lines unchanged. No rmcp-line edit in d-3-owned command/daemon manifests — REQ-RUN-0001/0002; REQ-DBSQ-0001.
6. Close ADR0020 Open items1-4 with dated decision text: read/write/atomic plus template extension, generic row mapping, schema/migration ownership, sc-storage/engine placement. Record the contract and create/delete extension decision with the pending owner ratification required in deliverable 3. Item5 synchronization stays deferred. Amend ADR0021 transform/extra-path decisions without inventing permissions — ADR-RUN-0020/0021.
7. Public storage functions return Result<T,E>, never panic; SQLite writer-thread panic makes every waiting caller receive an error instead of waiting indefinitely; implementation and tests are d-6 (ANC-036). Require the actual external no-panic rule and transaction-body analyzer on this sprint's changed storage code; missing rules block closure, no fake successful checks — ANC-035/036.

8. Apply the pre-dispatch ADR-RUN-0017/0203 Phase D amendments to the matching lines in template/Cargo.toml and template/workspace.template.toml: sc-observability/sc-observability-types >=1.5.0, utoipa >=6.0.0, utoipa-axum >=0.3.0, schemars >=1.2.3 and rmcp >=3.9 where present. The approved amendments are committed with this plan before any dispatch; this sprint owns the shared template manifest conversions, not a later permission to remove pins. Use the normal test suite for compatibility; consumer requirements remain open — ANC-016/037; ADR-RUN-0017/0203.

9. Record the owner-approved interim manifest check under ADR-RUN-0005 in docs/architecture.md: d-11 owns one enumeration/check used by compatible-generation; d-12 reuses it for packaged/test manifests and release enforcement. Consumer: release reviewer; gate: compatible0.3.0 packages; observed defect: restrictive SDK manifest defaults. This lint belongs in sc-lint; track randlee/sc-lint#936 (already filed). Remove the interim rule, release adapter and its dedicated fixtures once sc-lint ships the equivalent lint and sc-runtime adopts it; preserve ordinary generation/registry tests — ANC-016/037; ADR-RUN-0005.

### This sprint does not close
No real engine/cron policy implementation, generated composition or publication. d-6 implements generic SQLite; d-9 owns cron schema/migration/policy over atomic storage; d-11 runs real engine conformance; d-12 publishes0.3.0 after generated sanity. New transaction futures are not copied from atm-core typed-op channels and are not yet prototyped.
SQLite (d-6), Postgres (d-7) and MySQL (d-8) all implement the same sc-storage Storage<T> trait and its inherited generic AtomicStorage::transaction(spec, producer) operation; this single method runs several row operations as one atomic unit (ANC-032/033).
