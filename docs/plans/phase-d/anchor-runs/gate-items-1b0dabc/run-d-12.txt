# d-12: beads-cache-and-release

## Description

### Deliverables
1. Migrate actual beads-cache@8e883ee CacheScheduleStore and scheduler calls to published sc-storage/sc-runtime-db-sqlite/sc-cron0.3.0. Deliver the upstream migration PR and validate app+cron writes through its shared writer, preserving existing data and cron behavior — REQ-RUN-0002; REQ-CRON-0004; ADR-RUN-0020.
2. Own registry runner/workflow, archive rehearsal and actual eight-crate coordinated0.3.0 publication in dependency order with sc-storage first. Run fresh registry-only upstream/cron, server/rmcp and test-util helper consumers with the release-tested dependency combination, with advisory/source/native-identity checks — REQ-RUN-0002/0702; NFR-RUN-0007; ANC-012/016.
3. Update root README, release notes/project status and applicable controlled-host benchmark evidence to the actual published surface. Preserve kit/recovery rules and do not claim a source checkout or copied facade is the upstream migration — REQ-RUN-0702; NFR-RT-0001.

4. Remove tests/integration/cron-consumer/schema/Cargo.toml rmcp =3.8.0 pin in this sole-owned consumer manifest: use >=3.9 because3.9.x is the tested patched minimum for RUSTSEC-2026-0462 under the ADR-RUN-0203 amendment. Raising the floor removes older vulnerable releases; every later release from3.9 is admitted with no upper bound. Preserve the existing server/default-features selection and run the normal registry consumer tests and apply req:REQ-RUN-0002/package-caps (ADR-RUN-0203; ANC-016/037). Also convert tests/integration/cron-consumer/Cargo.toml Windows dev-dependencies to win32job >=2.0.3 and waitpid-any >=0.3.0, preserving purpose comments and running the normal Windows tests. d-3/d-5/d-9 retain their own pin-line edits; this sprint does not repeat them.

5. Reuse d-11's check_dependency_manifests(paths) on exact unpacked archives and generated-template defaults; wire it into archive rehearsal, registry consumer validation and upload. Own only input assembly and release fixtures. SDK registry requirements use >= floors with no upper bound; consumer pins are allowed (ANC-037). Remove the interim rule after equivalent sc-lint#936 release and adoption, as recorded by ADR-RUN-0005.

6. After final0.3.0 conversion and registry availability, refresh template/.sc-runtime/** with each supported profile's newest tested registry combination. Use d-11 generation code unchanged to deliver recommended Cargo.lock and matching .sc-runtime/tested-dependencies.json (ANC-038). Verify metadata/lock agreement and real --locked builds/tests.

### This sprint does not close
Generated app composition/transports are d-11-owned. This sprint starts after d-11 sanity closes and consumes its one manifest checker. No duplicate template wiring, template-only registry subject or second checker.

## Acceptance criteria

req:REQ-RUN-0002/published-consumers — Actual beads-cache migration PR/revision passes against crates.io0.3.0 packages, no path/patch/Git SDK source. App and schedule writes share its channel writer/file; run the upstream migration subject against published artifacts, distinct from d-11 generated-app criteria. Registry server/rmcp/helper subjects compile and execute; one native libsqlite3-sys identity in the graph, at >=0.39, no SQLx SQLite driver, target SQLite/rmcp advisories clear.
req:REQ-RUN-0002/release — Rehearse exact8crate archives before publication; package manifests/READMEs/features/comments match actual APIs and approved0.3.0. Publish sc-storage first then actual DAG order; all8 versions present, hash-identical retries only for missing uploads. Real defects halt/yank under owner policy and require coordinated replacement patch; transient failures never trigger yanks. Partial upload is not phase success.
req:REQ-RUN-0702/registry-proof — Workflow invokes python3 tests/registry/phase-d/run.py --version 0.3.0 --source crates-io with an isolated release-test lock, source/version assertions and actual upstream tests. Wrong or missing release/source, advisory/native mismatch or failed command exits nonzero. Controlled negatives test refusal; only actual post-publication consumer builds/tests prove delivery. Apply package-caps to the exact unpacked SDK manifests, not consumer-owned pins.
Required commands: just lint; just test; cargo build --workspace; sc-lint lint sc-boundary --root . --config sc-lint.toml; kit package/rehearsal and fresh registry runner the registry consumers; cargo deny check advisories for every registry subject; python3 scripts/benchmark/check_release_evidence.py with controlled-host evidence matching source-equivalence policy. Root README/release notes match package contents. d-11 generated integration is separately required for phase acceptance.
req:REQ-RUN-0002/publication-gate — Runner/migration preparation first. No archive/consumer validation or upload until run-d-11.group-sanity status=closed and its callable manifest-check handoff is available, owner ratification recorded and both external rules (sc-lint#931 no-panic and transaction-body analyzer) delivered and passing on all changed storage code. Missing either rule blocks publication; no implicit waiver. Then final0.3.0 manifest/lock conversion, exact8-archive rehearsal with package-caps passing before upload, and fresh registry proof invoking the same check at the registry consumers. The d-12 dev bead is blocked by d-11 sanity; immediately before first upload, check the publication predicate again.
req:REQ-RUN-0002/upstream-subject — Exact close predicate: upstream beads-cache PR open with CI green at recorded SHA using published0.3.0 SDKs, URL/SHA in owned consumer README. Maintainer=user/randlee; merge not required. No response or CI failure leaves sprint open with explicit external follow-up. No local path/patch/Git SDK substitute. sc-command package exports/docs match closed d-10; cargo tree checks selected native graph, not lockfile.
All changed public storage functions are typed Result/no-panic. Actual writer-panic callers receive typed errors; required no-panic/transaction analyzer evidence is not replaced by promises or a superficial grep. cargo build --workspace passes against the final coordinated train at this closure.
req:REQ-RUN-0002/package-caps — Call d-11's single manifest check on exact unpacked SDK manifests and generated-template defaults: registry requirements must use >= tested floors with no upper bound (ANC-037). A violation fails rehearsal, registry consumer proof and upload. Consumer-owned pins are permitted and outside this default-policy check. d-12 owns input assembly/wiring; the checker stays d-11-owned and root rusqlite stays d-6-owned.
req:REQ-RUN-0002/package-caps-check — Through the same release entrypoint, controlled SDK-default fixtures with an upper bound or exact pin fail and an open-floor fixture passes. Run python3 -m unittest discover -s tests/registry/phase-d -p "test_manifest_gate.py". Actual archives and both registry registry consumer proof must also pass the check. This remains the ADR-RUN-0005 interim rule pending equivalent sc-lint#936 release and adoption.
req:REQ-RUN-0002/preserved-cron — In the actual upstream migration, the default app and cron data use the same SQLite file; the existing consumer tests verify rejection of a second active schedule with the same name and of a new schedule row at the embedding app's configured limit. Reuse the delivered cron behavior and existing upstream cases; do not build a second policy implementation (ANC-021/030/031).
req:REQ-RUN-0002/admitted-requirements — Every registry requirement this sprint writes uses >= its tested floor with no upper bound: SDK sibling/consumer >=0.3.0, rmcp >=3.9, win32job >=2.0.3 and waitpid-any >=0.3.0; other requirements follow the same open-floor rule. Inspect unpacked manifests and execute normal consumer tests without rewriting SDK requirements or republishing. The release-test lock and --version0.3.0/archive hashes identify the tested release, not restrictive manifest pins. Consumers may choose their own pins (ANC-037).
req:REQ-RUN-0002/release-recommendations — Release-generated applications ship the tested latest-allowed registry Cargo.lock and .sc-runtime/tested-dependencies.json from the same actual profile build/test run (ANC-038). Metadata enumerates every locked package name/version/source and release/toolchain/profile identity, matches Cargo.lock, and is readable for later revert/upgrade tooling. Consumers can keep, replace or update the recommended lock and pin their own requirements. Use d-11 generation code unchanged; d-12 refreshes only recommendation inputs and release proof.
