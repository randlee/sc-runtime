# d-6: sqlite-storage

## Description

### Deliverables
1. Implement the shared sc-storage Storage<T> trait and its generic transaction operation that runs several row operations as one atomic unit over a bounded channel whose design is adapted from atm-core (copied code, no dependency), single writer and reader pool. The writer thread exclusively owns the only write-mode SQLite connection; reader workers open read-only connections. Futures are NEW work, not copied typed operations. Read-write body is one writer message/savepoint; queue batches commit together and replies follow commit. Read-only may use reader pool — REQ-DBSQ-0002/0003; ANC-022..027/033.
2. Enforce transaction-body non-suspension: Pending rolls back with typed error, failed/panicked body never commits. Public storage APIs return typed Result and never panic; writer panic terminates/fails every pending/in-flight/queued caller without hangs — NFR-RUN-0002; ANC-035/036. Qualify actual external analyzer/no-panic rules for changed code, never substitute runtime polling for static analysis.
3. Generic row/migration/codec implementation contains no cron/application table type, schema or SQL. Consumer supplies row descriptors; all consumer policies live above storage. No sc-cron dependency/feature — ANC-032/034. Consume real row/options/codec declarations frozen in d-5; implement the concrete database API, with no duplicate definitions.
4. Use the shared root rusqlite requirement >=0.41 with no upper bound; run the normal SQLite test suite. Thin generated SQLite storage consumes the generic backend and application-owned schema and removes SQLx SQLite/cache/config — REQ-DBSQ-0001; REQ-RUN-0308; ANC-012/028/037.

5. Retire the public raw-SQL SqliteWriter/WriterConn/SqlValue/SqliteWriterError facade in0.3.0; raw connection/execute helpers become crate-private behind generic Storage<T>. Implement inherent SqliteDatabase open/storage/shutdown/wait_closed with SqliteOpenOptions, not a factory trait. Amend REQ-DBSQ-0001/0002 and its architecture/boundary public facade to the final implemented dependency/API surface, following d-5 declarations. All owned registry requirements use >= tested floors without upper bounds (ANC-037).

### This sprint does not close
Cron schema/domain policy/migration are d-9; real cron conformance and complete generated/mixed layouts are d-11; actual upstream/publication d-12. Backend tests use generic rows and do not contain a CronRow codec or cron SQL.
This sprint implements Storage<T> for SqliteStore<T> using that shared trait, with no SQLite-specific parallel storage trait; it implements the SAME AtomicStorage::transaction(spec, producer) method as one writer message/savepoint.
