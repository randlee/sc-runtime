# d-5: storage-contract

## Description

### Deliverables
1. SQLite, Postgres and MySQL all implement one shared sc-storage Storage<T> trait and its single AtomicStorage::transaction(spec, producer) operation, which runs several row operations as one atomic unit (ANC-032/033). Define real std-only sc-storage Storage<T>, generic row/atomic transaction/error contracts and generic test doubles. No consumer table type, schema or SQL is in a backend (ANC-034). Prototype a fresh owned Send+'static future per retry; transaction properties are only name and read-only/read-write (ANC-033). Preserve measured transaction observations: name, queue wait, run time, row operations and outcome.
2. Freeze row descriptors with validated Identifier values, typed StorageError codes/retryability/source/recovery, and template WidgetStorage/OpenWidgetStore/StoresView extensions preserving existing create/get/delete (REQ-RUN-0201/0328/0330). Public storage functions return typed Results and never panic (ANC-035). Backend factory entry points are concrete inherent methods; sc-command owns Transform and plain storage_read/storage_write functions in d-10, with no StorageCommands or SqliteDatabaseFactory trait.
3. Define CronRow and an intentionally open CronStorage domain interface in sc-cron. CronStore wraps a backend Storage<CronRow>; it does not implement a public raw-write supertrait that bypasses fencing/name/row-limit policy. Declare the one shared generic double and conformance suite; d-9 implements cron policy once and owns its domain suite (REQ-CRON-0004/0005/0020/0021).
4. Register sc-storage and shared SDK/backend dependencies in root/template registries and boundaries including the cron Windows dev-dependency lines, with >= tested floors and no upper bound (ANC-037). Root owns rusqlite >=0.41. Make only the legacy SQLite API/dependency adaptations necessary for this contract branch's workspace build; the named files pass to d-9 for removal after contract sanity. Preserve existing legacy tests. Development remains0.2.0; release is coordinated0.3.0.
5. Amend REQ-RUN-0002/0702 and NFR-RUN-0009 for eight public0.3.0 crates and shared-storage typed errors; amend REQ-DBSQ-0001/0002 for sc-storage/Tokio plus the generic async writer surface; amend REQ-CRON-0001/0004 and NFR-CRON-0001 for sc-storage/sc-command domain policy and removal of direct cron rusqlite. Amend ADR-RUN-0020/0021 with the exact tested contracts. Owner (randlee) ratification of the proposed extension/transaction/row/migration shape is PENDING: record it and change both ADR statuses to Active before this sprint closes or d-6..d-12 start. Synchronization and unspecified permissions remain deferred.
6. Record the existing one-checker interim rule in ADR-RUN-0005: d-3 owns it, d-11 uses it for generation, d-12 for unpacked archives/upload. Consumer=release reviewer; defect=restrictive SDK manifest defaults; remove after equivalent sc-lint#936 release and adoption. Record the approved eight-package tradeoff in ADR-RUN-0020: only SQLite gets the new published engine crate this phase; table-neutral Postgres/MySQL implementations remain generated, so fixes to that generated engine code require template updates/regeneration, not cargo update. Do not claim otherwise.

### This sprint does not close
No production engine or cron implementation, generated integration or publication. Real contract types/doubles compile and the workspace builds. Exact new transaction futures are prototype risk, not copied atm-core typed operations. D-6..d-10 consume the closed, ratified contract.
Register tests/support/storage and tests/support/cron-storage as allowed_test_double_paths in the relevant storage/cron boundary manifests and sc-lint configuration; these are private test support. Hand only each specific boundary facade file to d-6/d-9 after contract sanity. Convert sc-cron Windows dev requirements win32job >=2.0.3 and waitpid-any >=0.3.0 here; d-9 leaves those lines unchanged (ANC-037).

## Acceptance criteria

boundary:storage-contract — Real exported row/storage/transaction/error/extension contracts and generic double compile; tests import production definitions, not replicas. Prototype verifies fresh owned retry bodies, atomic rollback on controlled Pending/error, exactly name/mode properties and controlled-clock transaction observations (ANC-033). Demonstrate multi-row-type support or the tested single-row-type limitation; if neither contract passes atomic/retry/safety cases, closure stays blocked.
boundary:storage-contract/ratification — Record randlee ratification and Active ADR-RUN-0020/0021 with the exact tested shape before closure. The named REQ/NFR amendments match the eight-package0.3.0 architecture. Future consumers never start against merely Proposed ADRs.
boundary:storage-contract/errors — StorageError exposes stable code, retryability, std::error::Error source and recovery guidance; mappings preserve those as typed cause/details without replacing existing domain error codes. Identifier construction returns typed errors and engines quote identifiers/parameterize values; descriptors contain no raw SQL.
boundary:storage-contract/workspace — cargo build --workspace and existing sc-cron legacy SQLite tests pass after necessary inherited rusqlite0.41 adaptations. Retain legacy assertions in the shared conformance suite. Generic test support contains no CronRow or domain policy; sc-storage is std-only.
Required: cargo test -p sc-storage; cargo test --manifest-path tests/support/storage/Cargo.toml; cargo test -p sc-cron; cargo test --manifest-path tests/contracts/storage-v2/Cargo.toml; cargo build --workspace; sc-lint lint sc-boundary --root . --config sc-lint.toml. The actual sc-lint#931 no-panic and external transaction-body analyzer must exist and pass on changed storage code before closure. Controlled unsafe-await/unmarked-helper/Pending cases stay separate from static proof; no implicit waiver.
