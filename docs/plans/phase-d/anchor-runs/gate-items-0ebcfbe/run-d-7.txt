# d-7: postgres-storage

## Description

### Deliverables

1. Implement the agreed Storage<T> backend using direct sqlx-core/sqlx-postgres Postgres pool/migration code; typed row mapping stays in backend/consumer contract, no raw cross-engine query API — REQ-RUN-0328; PRD-STO2.
2. Replace widget-specific store functions only when the typed consumer calls compile; preserve live-engine transaction/error semantics and feature gates — ADR0020; REQ-RUN-0302.

3. Implement the shared sc-storage Storage<T> trait, generic row mapping and engine factory contract and generated-key create/delete primitives using arbitrary conformance rows and generic atomic transaction begin/commit/retry. App supplies schema mapping; backend has no specific consumer table code — ANC-032/033/034/035.
4. Replace sqlx umbrella with direct sqlx-core + engine driver + sqlx-macros requirements, retaining only necessary features; qualify real query macros, migration/offline/CLI paths, not just a successful resolver — REQ-RUN-0002; NFR-RUN-0007.

### This sprint does not close
Real production composition, generated database security and registry migration are d-11; no generator/sync/permission feature is added.
SQLite (d-6), Postgres (d-7) and MySQL (d-8) all implement the same sc-storage Storage<T> trait and its inherited generic AtomicStorage::transaction(spec, producer) operation; this single method runs several row operations as one atomic unit (ANC-032/033). This sprint implements Storage<T> for PostgresStore<T> using that shared trait, with no Postgres-specific parallel storage trait; it implements the SAME AtomicStorage::transaction(spec, producer) method with SERIALIZABLE transactions and retry.
