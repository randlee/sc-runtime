# d-6: sqlite-storage

## Description

### Deliverables
1. Implement the shared sc-storage Storage<T> trait and its generic transaction operation that runs several row operations as one atomic unit over a bounded channel whose design is adapted from atm-core (copied code, no dependency), single writer and reader pool. Futures are NEW work, not copied typed operations. Read-write body is one writer message/savepoint; queue batches commit together and replies follow commit. Read-only may use reader pool — REQ-DBSQ-0002/0003; ANC-022..027/033.
2. Enforce transaction-body non-suspension: Pending rolls back with typed error, failed/panicked body never commits. Public storage APIs return typed Result and never panic; writer panic terminates/fails every pending/in-flight/queued caller without hangs — NFR-RUN-0002; ANC-035/036. Qualify actual external analyzer/no-panic rules for changed code, never substitute runtime polling for static analysis.
3. Generic row/migration/codec implementation contains no cron/application table type, schema or SQL. Consumer supplies row descriptors; all consumer policies live above storage. No sc-cron dependency/feature — ANC-032/034. Implement real factory/codec traits frozen in d-5, no duplicate definitions.
4. Use the shared root rusqlite requirement >=0.41 with no upper bound; run real minimum/latest SQLite tests. Thin generated SQLite storage consumes the generic backend and application-owned schema and removes SQLx SQLite/cache/config — REQ-DBSQ-0001; REQ-RUN-0308; ANC-012/017/028/037.

### This sprint does not close
Cron schema/domain policy/migration are d-9; real cron conformance and complete generated/mixed layouts are d-11; actual upstream/publication d-12. Backend tests use generic rows and do not contain a CronRow codec or cron SQL.
SQLite (d-6), Postgres (d-7) and MySQL (d-8) all implement the same sc-storage Storage<T> trait and its inherited generic AtomicStorage::transaction(spec, producer) operation; this single method runs several row operations as one atomic unit (ANC-032/033). This sprint implements Storage<T> for SqliteStore<T> using that shared trait, with no SQLite-specific parallel storage trait; it implements the SAME AtomicStorage::transaction(spec, producer) method as one writer message/savepoint.
